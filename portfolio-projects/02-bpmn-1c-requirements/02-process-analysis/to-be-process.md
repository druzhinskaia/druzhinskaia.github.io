# Целевой процесс

1. Менеджер вводит обязательные поля; система проверяет значения и активного ответственного. При ошибке документ не создаётся.
2. Система сохраняет документ, рассчитывает SLA и ставит уведомление в очередь.
3. Высокий приоритет или специальная категория → На согласовании; остальные → Новая.
4. Руководитель согласует, отклоняет с причиной или запрашивает уточнение. После уточнения система повторно определяет необходимость согласования.
5. Менеджер принимает разрешённую заявку в работу; исполнитель фиксирует результат в Выполнена.
6. Менеджер принимает результат → Закрыта и closed_at; либо возвращает в работу с причиной.
7. Фоновый контроль открытых заявок создаёт одно логическое уведомление просрочки; повторы доставки не дублируют событие.

Правила: `../06-specification/status-transitions.md` и `sla-and-notifications.md`. Диаграмма иллюстрирует эти правила, не заменяет таблицу ролей.
