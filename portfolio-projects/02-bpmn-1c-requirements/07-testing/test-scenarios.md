# Сценарии приёмки в 1С

Все TS ниже **ожидают выполнения в целевой 1С**. Эталонные тесты Python проверяют только доступную модель правил.

| ID | Ввод / действие | Ожидаемый результат |
|---|---|---|
| TS-01 | создать без категории и приоритета | ошибка полей; записи, истории и уведомления нет |
| TS-02 | высокий приоритет, пятница 09:00, календарь без праздников | due_at пятница 18:00 (9 рабочих часов) |
| TS-03 | средний приоритет, все поля, активный ответственный | Новая, один документ, одно уведомление |
| TS-04 | высокий приоритет или category.requires_approval=true | сразу На согласовании; В работе запрещён до решения |
| TS-05 | открытая заявка, now равен due_at, затем на секунду позже | равенство не просрочка; позже одно событие руководителю |
| TS-06 | Новая → В работе менеджером | старая/новая стадии, пользователь и время в защищённой истории |
| TS-07 | 3 открытых заявки: одна просрочена, две не просрочены | отчёт показывает ровно одну просрочку, правильных ответственных и статусы |
| TS-08 | менеджер меняет справочник; администратор меняет справочник | менеджеру отказ; администратору разрешено, действие записано |
| TS-09 | свободный текст статуса или Новая → Закрыта | сохранение запрещено |
| TS-10 | категория без правила или неактивный ответственный | сохранить нельзя до выбора активного разрешённого пользователя |
| TS-11 | создание, повторная обработка очереди, переназначение | одно событие на создание; одно на новую версию назначения |
| TS-12 | руководитель согласует / отказывает / просит уточнение | Согласована / Отклонена с причиной / Требует уточнения с вопросом |
| TS-13 | после уточнения изменена категория на requires_approval | возвращается На согласовании, а не напрямую В работе |
| TS-14 | исполнитель В работе → Выполнена; менеджер принимает / возвращает | closed_at пуст до принятия; затем Закрыта и время / В работе с причиной |
| TS-15 | воскресенье, праздник и явно рабочая суббота; старт в 18:00 | учитываются только интервалы календаря, старт переносится; сверить с reference/sla.py |
| TS-16 | сменить приоритет через рабочий день; удержать на уточнении | новый срок от created_at, паузы нет, изменение записано |
| TS-17 | транспорт недоступен, затем доступен; выполнить >5 попыток | интервалы >=15 минут, доставка не дублируется, после лимита видимая ошибка |
| TS-18 | попытка удалить историю обычным пользователем | отказ, журнал сохраняется |
| TS-19 | новичок создаёт заявку по экранным подсказкам | обязательные поля видны, ошибки указывают поле, задача выполнена без внешней инструкции |
| TS-20 | отчёт на 10 000 заявок, 20 пользователей, стенд согласован | 95-й процентиль <=10 секунд по 30 запускам; параметры и результаты приложены |
| TS-21 | окно формы 1366×768, масштаб 100%, без прокрутки | тема, категория, приоритет, ответственный и срок видны на первом экране |

TS-20 — целевое требование, не пройденный нагрузочный тест. Версии, ресурсы стенда и журнал измерений фиксируются до запуска.
